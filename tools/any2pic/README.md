# 视觉传输（Any2Pic）

一个纯前端、离线运行的“文件 ⇄ 图像页”传输工具。发送端把文件编码为带蓝白边框标尺的色块图像序列；接收端可导入图片、用摄像头拍摄或从屏幕选区连续收集页面，收齐后自动还原并下载文件。

> 入口文件：`any2pic.html`  
> 设计说明：`视觉传输 · 高密度编码 – 技术设计文档（完整版）.md`

---

## 功能概览

- **三种编码模式**
  - 黑白：1 bit / 色块，识别容错相对更好；
  - 色板 2 bit：4 色；
  - 色板 3 bit：8 色，默认模式，单位页面承载更多数据。
- **可配置参数**：色块大小、图片边长、纠错冗余比例。
- **传输页轮播**：支持上一页、下一页、暂停/播放以及 1.2 / 2 / 3 / 5 秒播放间隔。
- **多种解码输入**：多张图片导入、摄像头拍照/自动扫描、屏幕选区扫描。
- **页状态矩阵**：显示每页 `✅ 已收集`、`🟠 未检测`、`❌ 有错误`。
- **自动还原**：页号完整、所有页 CRC 通过后，自动拼接、校验并显示下载按钮。
- **自适应无损压缩**：编码时自动尝试 LZSS；只有压缩结果至少节省 2% 且节省超过 32B 时才启用。
- **摄像头增强**：方向检查、白平衡/对比增强、可选镜头校正、蓝框四角拟合和透视归一化。
- **诊断视图**：在出现解析问题时，可查看原始图、预处理图、裁剪图、去噪图、采样点与标尺跳变信息。

所有文件、图片和计算均在浏览器本地完成，不会上传到服务器。

## 快速开始

### 1. 打开页面

直接用浏览器打开 `any2pic.html`。

如需使用摄像头或屏幕共享，建议通过本地 HTTP 服务访问，并使用最新版 Chrome 或 Edge。例如：

```bash
python -m http.server 4174 --directory "D:/Github/any2pic/ws"
```

然后打开：`http://127.0.0.1:4174/any2pic.html`

浏览器会在需要时请求摄像头或屏幕共享权限。

### 2. 编码文件

1. 在顶部配置区选择参数，点击“应用配置”。
2. 推荐先使用默认配置：
   - 色块大小：`8 px`
   - 图片边长：`1208 px`
   - 模式：`色板 3bit`
   - 纠错冗余：`15%`
3. 在“编码”页拖入文件，或点击“选择文件”。
4. 等待生成传输页；状态行会显示：
   - 是否启用 LZSS 压缩；
   - 原始文件与传输数据大小；
   - 实际总页数；
   - 每页净载荷。
5. 使用轮播发送页面，或点击“下载全部”保存传输页图片。导出名称为：`原文件名_slice_0001_of_0012.png`。

### 3. 解码并自动还原

接收端打开同一页面，切换至“解码”。任选一种方式收集页面：

- **导入图片**：拖入或多选所有传输页图片；可乱序导入。
- **摄像头**：点击“打开摄像头”，手动点“拍照添加”，或点“自动扫描”连续识别。
- **屏幕选区**：点击“屏幕选区”，在共享画面中拖动框选完整传输图区域，再点击“开始扫描选区”。

收到任意有效页面后，会显示页状态矩阵。例如：

```text
01 ✅  02 ✅  03 🟠  04 ❌
```

含义：

- `✅`：该页已通过 CRC 校验并收集；
- `🟠`：尚未检测到该页；
- `❌`：该页识别到但解析或校验失败；请重新导入/拍摄该页。

当所有页面都变为 `✅` 后，页面会自动：

1. 按页号拼接数据；
2. 按需要进行 LZSS 解压；
3. 执行文件级 SHA-256 校验；
4. 在解码操作区顶部显示醒目的“文件已还原”下载卡片。

点击“下载文件”即可保存。

## 传输建议

### 屏幕到屏幕

这是最稳定的方式。

- 屏幕选区必须覆盖**完整蓝白棋盘边框**；
- 传输页显示比例应尽量保持整数缩放，避免浏览器或系统的极端缩放；
- 接收端正在识别时，建议轮播间隔使用 **3 秒或 5 秒**；
- 若提示“页面切换过快”，先暂停发送或把播放间隔调慢。

### 摄像头拍摄

- 让整张传输图和四周蓝白边框完整进入画面；
- 尽量正对屏幕，避免明显倾斜、屏幕反光和运动模糊；
- 默认开启“摄像头图像增强”和“轻度镜头校正”；
- 广角畸变明显时可尝试“中度”，若边缘异常可改为“关闭”；
- 拍摄距离应保证单个色块在相机画面中有足够像素；远距离拍摄时优先降低密度，例如增大色块或改用黑白模式。

### 参数选择

| 目标 | 推荐做法 |
|---|---|
| 优先稳定 | 黑白 1bit、较大色块、较高纠错冗余 |
| 屏幕选区快速传输 | 色板 3bit、默认 8px 色块、15% 冗余 |
| 摄像头实拍 | 色板 2bit 或黑白、增大色块、播放 ≥ 3 秒 |
| 文本/JSON/CSV/代码 | 保持自动压缩，通常能明显减少页数 |
| JPG/PNG/ZIP/MP4 等已压缩文件 | 自动压缩通常不会启用，这是正常现象 |

顶部“传输预设”可一键填入：稳定实拍、平衡传输、高速屏幕三组参数；选择后点击“应用配置”生效。

> 改变顶部配置会清空当前解码收集批次，避免不同参数的页面混用。

## 常见问题

### 1. 显示“标尺采样不稳定”

原因通常是未包含完整边框、图像倾斜严重、反光、模糊或选区包含了黑边。

处理方法：

1. 确保框选/拍摄范围包含完整蓝白边框；
2. 摄像头场景下稳定设备并尽量正对显示屏；
3. 降低屏幕亮度反光、避免环境强光；
4. 传输端改用更大色块或更低位深模式；
5. 查看诊断图，确认采样点是否落在正确网格上。

### 2. 页面总是缺几页

- 查看页状态矩阵中的 `🟠` 页号；页面会直接提示下一步需要补传的页号；
- 手动切换发送端到缺失页并停留更久；
- 屏幕扫描时增大播放间隔；
- 导入图片时可直接补充缺失页，无需重新导入成功页。

### 3. 出现“播放过快”提示

接收端还未完成当前页解析，发送端已经切换到下一页。请把发送端播放间隔改为 **3 秒或更长**，或先用手动翻页测试。

### 4. 历史编码图片自动还原失败

历史图片可能使用旧版文件包格式；v3 新页面使用固定协议签名和会话 ID。请注意：

- 同一批次只能使用同一版本、同一配置生成的页面；
- 历史图片不要与新版图片混合导入；
- 对历史多页文件，优先一次性导入全部原始传输图片；
- 如果仍失败，请保留页面和诊断信息，避免重新编码覆盖问题样本。

### 5. 摄像头权限或屏幕共享不可用

- 使用 `http://localhost` / `http://127.0.0.1` 或 HTTPS 页面；
- 在浏览器地址栏允许摄像头/屏幕共享权限；
- 关闭占用摄像头的其他应用后重试；
- 建议使用最新版 Chrome 或 Edge。

## 当前限制

- 文件会一次性读入浏览器内存，不适合非常大的文件或超长页序列；
- 当前页级 RS 冗余已生成，但尚未实现完整的 Reed-Solomon 误码纠正；CRC 失败的页面仍需重新收集；
- 强透视、严重模糊、摩尔纹、色偏或反光可能导致色块误判；
- 页面目前没有传输会话 ID，不应混合多个不同文件或不同配置批次的页面；
- 旧版与新版文件包存在兼容分支，请对重要历史文件做一次实际闭环验证。
