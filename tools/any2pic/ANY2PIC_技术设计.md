# 视觉传输 · 高密度编码 — 技术设计文档（实现基线）

**版本**：3.0（实现基线）  
**更新日期**：2026-08-25  
**实现文件**：`any2pic.html`  
**状态**：持续迭代；本文以当前单页前端实现为准，不将规划能力表述为已实现能力。

---

## 1. 目标与边界

视觉传输是一个纯前端、离线运行的文件图像传输工具：发送端把文件编码为带蓝白边框标尺的色块图像序列；接收端可从导入图片、摄像头或屏幕选区读取页面，收齐并校验全部页面后自动还原为下载文件。

当前目标：

- 支持黑白 1bit、色板 2bit、色板 3bit 三种色块模式；
- 支持文件导入、摄像头拍照/自动扫描、屏幕选区扫描；
- 以页 CRC32、文件 SHA-256、页状态矩阵提供可见的传输状态；
- 在明显收益时启用轻量 LZSS 无损压缩；
- 不上传文件或图像数据，全部处理在浏览器本地完成。

当前不承诺：真正的 Reed-Solomon 误码纠正、针对重度透视/模糊/强反光实拍的稳定识别、流式大文件传输或旧协议所有历史样本的无条件兼容。

## 2. 架构与主要模块

```text
UI（编码页 / 解码页 / 状态矩阵 / 下载结果区）
  ├─ 编码：FileReader → 自适应压缩 → 分页 → Canvas 绘制
  ├─ 解码：ImageData → 边框定位/透视归一化 → 网格采样 → 页解析
  ├─ 收集：成功页、缺失页、失败页、去重与重试
  └─ 还原：按页号拼接 → 可选 LZSS 解压 → SHA-256 → Blob 下载
基础：Canvas 2D、Web Crypto、File API、getUserMedia、getDisplayMedia
```

| 模块 | 当前职责 |
|---|---|
| `encodeFileToPages` | 读取文件、尝试 LZSS、构造文件包、分页并绘制 Canvas 页面 |
| `decodeImageFromSource` | 从图片或 Canvas 采样位流、解析页头与第 0 页文件元数据 |
| `sampleRulerEdges` | 以蓝白边框的多点投票统计四边跳变并确定网格 |
| 摄像头预处理 | 方向尝试、白平衡/对比增强、可选径向校正、四角透视归一化 |
| 屏幕选区 | 处理 `object-fit: contain` 的坐标映射、稳定帧识别与过快切页提示 |
| `queueAutomaticAssembly` | 仅在页齐全且 CRC 通过时启动自动还原 |

## 3. 图像页面格式

### 3.1 可视结构

- 图像尺寸由 `imageSize` 决定，默认 `1208 × 1208` px。
- 色块尺寸由 `blockSize` 决定，默认 `8` px。
- 总色块数必须是奇数；默认 `1208 / 8 = 151`。
- 外圈占 1 个色块宽，按 `(row + col) % 2` 绘制蓝白棋盘格，作为定位标尺。
- 内部 `(N - 2) × (N - 2)` 区域承载同步头、页头、数据、ECC 和零填充。

### 3.2 页级帧

每页有效区最前方固定为同步头 `0xAAAA`（16 bit），随后为 16B 页头：

| 字段 | 大小 | 编码 | 说明 |
|---|---:|---|---|
| `totalPages` | 2B | Uint16 BE | 总页数 |
| `pageIndex` | 2B | Uint16 BE | 从 0 开始的页号 |
| `dataLen` | 4B | Uint32 BE | 本页有效数据位数 |
| `crc32` | 4B | Uint32 BE | 本页有效数据 CRC32 |
| `eccLen` | 2B | Uint16 BE | 纠错冗余字节数 |
| `reserved` | 2B | 预留 | 当前未使用 |

当前实现会生成 GF(256) 形式的 RS 冗余字节，但 `rsDecode` 目前仅返回数据段，**尚未实现真实的误码定位与纠正**。因此当前可靠性主要来自网格采样、CRC32 和重采集机制；不得把它描述为已具备完整 RS 纠错能力。

## 4. 文件包与协议兼容性

### 4.1 新版文件包（当前编码输出）

新版在文件名之后设置显式标记，避免将旧版文件数据误解为压缩元数据：

```text
magic(4B, 0xDEADBEEF)
+ fileNameLen(2B, UTF-8 字节数)
+ fileName(NB)
+ protocolSignature(3B, 0x56 0x54 0x03，即 "VT" + v3)
+ compressionType(1B)
+ sessionId(8B, 随机会话 ID)
+ originalSize(4B, Uint32 BE)
+ transportSize(4B, Uint32 BE)
+ originalSha256(32B)
+ transportData(transportSize B)
```

页头的 2B `reserved` 字段现用于 `sessionTag`（会话 ID 的前 16 bit），用于在收集阶段快速排除另一批次页面。`compressionType`：

- `0`：未压缩；`transportData` 即原文件数据；
- `1`：LZSS；`transportData` 是压缩数据，需解压至 `originalSize`。

文件级 SHA-256 计算对象永远是**原始文件数据**，而不是压缩数据。

### 4.2 历史文件包（兼容读取）

早期图片没有 `envelopeMarker`、`transportSize`，其格式为：

```text
magic(4B) + fileNameLen(2B) + fileName(NB) + fileSize(4B)
+ originalData(fileSize B) + sha256(32B)
```

解码器通过文件名后的 3B 固定签名 `0x56 0x54 0x03` 判断 v3；签名不匹配时按旧版未压缩包处理。多字节签名避免把旧版文件数据误判为新协议元数据。

**兼容性约束**：历史多页图片应以旧协议的 `fileSize` 为准截取原始负载；旧 SHA 位于完整数据流尾部，可能跨页。历史样本的兼容解码必须保留页序与原始图片，不应与新版压缩页混合收集。对于首次遇到的历史大文件，应做一次导入图片闭环验证后再依赖其自动还原结果。

## 5. 编码流程与容量

1. `FileReader` 读取文件为 `Uint8Array`。
2. 计算原始文件 SHA-256。
3. 调用 `lzssCompress` 生成候选压缩数据。
4. 仅当 `压缩数据长度 + 32B < 原始长度 × 98%` 时启用压缩；否则传输原始数据。
5. 构造新版文件包，转换为位流，按每页有效载荷切分。
6. 每页写入页头、CRC32、ECC 冗余，绘制蓝白边框与数据色块。
7. UI 显示原始大小、压缩后的传输大小（若启用）、实际页数及每页净载荷。

容量计算必须以实际帧结构为准：

```text
rawBits = (N - 2)² × bpp
frameOverhead = syncHeader(2B) + pageHeader(16B)
可用字节 = floor(rawBits / 8) - frameOverhead
净载荷 = 满足 payload + ceil(payload × eccLevel) <= 可用字节 的最大 payload
```

| 模式 | 每色块位数 |
|---|---:|
| `bw` | 1 |
| `color2` | 2 |
| `color3` | 3 |

文件名长度按 UTF-8 **字节数**而非 JavaScript 字符数存储。

## 6. 解码、状态矩阵与自动还原

### 6.1 单页解码

1. 从 Image / Canvas 获取 `ImageData`。
2. 摄像头来源可执行方向、调色、镜头校正和透视归一化；导入图/屏幕图使用基础边框裁剪流程。
3. HSV 蓝色检测定位边框；摄像头模式进一步拟合四条边线，计算四角并执行单应性透视校正。
4. 对四边标尺按预期网格中心进行多点投票；统计四边蓝白跳变。
5. 采样数据网格：黑白模式用二值化邻域多数投票；色板模式用 3×3 RGB 平均值匹配最近色板。
6. 定位同步头，尝试有限位偏移，读取页头并验证 CRC32。
7. 第 0 页额外解析文件包元数据；其余页返回原始页负载。

### 6.2 页状态

成功读取任一页并得到 `totalPages` 后，界面渲染全部页格：

- `01 ✅`：CRC 通过且已收集；
- `02 🟠`：尚未检测到；
- `03 ❌`：可归属该页且本次解析/校验失败；
- 无法识别页号的失败记录单独保存，不强行映射到页格。

摄像头和屏幕自动扫描对重复失败进行限频/去重，避免单帧错误刷满失败记录。

### 6.3 自动还原

自动还原触发条件：

1. 已存在第 0 页；
2. 收集数量等于 `totalPages`；
3. 每页 `totalPages` 一致；
4. 每页 CRC 已通过；
5. 当前没有进行中的还原，也没有已完成的同批次还原。

满足后，系统先验证所有页的 `sessionTag` 与第 0 页一致，再按 `pageIndex` 排序拼接。v3 按 `transportSize` 截取传输流；旧版按 `fileSize + 32B SHA` 从完整流中截取。若 `compressionType = 1` 则调用 LZSS 解压到 `originalSize`；对结果计算 SHA-256。校验通过后，顶部醒目结果区显示文件名、大小、压缩说明及下载按钮。已移除主界面的手动“拼接还原”按钮。

## 7. 图像采集与鲁棒性

### 7.1 摄像头

当前摄像头链路具备：

- 0° / 90° / 180° / 270° 方向候选与蓝框评分；
- 自动白平衡与适度对比度增强；
- 可选径向畸变近似校正（关闭 / 轻度 / 中度）；
- 蓝框四边线拟合、四角求交和单应性透视归一化；
- 手动拍照添加与自动扫描均使用同一预处理配置；
- 调试图可显示原图、方向处理、增强/镜头处理、裁剪、二值化与采样点。

实拍仍依赖基本条件：完整边框可见、色块在画面中有足够像素宽度、拍摄时画面稳定、避免高光覆盖蓝色标尺。

### 7.2 屏幕选区

屏幕采集使用 `getDisplayMedia`。选区坐标会根据视频实际显示区域修正 `object-fit: contain` 产生的黑边偏移。扫描时使用单帧在途解码、低分辨率帧签名与连续 2 帧稳定门槛：画面变化后先等待稳定再解析；若上一页仍在解析时已经切页，则提示降低编码页播放速度（建议至少 3 秒）。

### 7.3 标尺采样

标尺和数据区去噪逻辑分离：标尺直接在原始/透视校正图上采样，不经过二值化开运算。预期网格模式对每个格中心的多点样本投票，允许小范围四边计数差异；只有差异超过阈值且不满足预期网格约束时才拒绝该页。

## 8. UI 与诊断

- 编码面板：文件选择、容量/压缩信息、页轮播及播放间隔（1.2 / 2 / 3 / 5 秒）、下载全部页面；内置“稳定实拍 / 平衡传输 / 高速屏幕”预设。
- 导出图片命名：`原文件名_slice_0001_of_0012.png`，文件名中的 Windows 非法字符会替换为下划线。
- 解码面板：图片多选导入、摄像头、屏幕选区、自动扫描、清空、页状态矩阵、成功页列表、缺失页列表、失败记录和诊断图；缺页区域会直接提示下一步需要补传的页号。
- 成功还原后的下载区域位于解码操作区上方，以绿色结果卡和大号下载按钮呈现。
- 更改编码参数会清空当前接收批次，避免不同配置页面混合。

## 9. 已知限制与后续优先级

1. `rsDecode` 尚未完成真正 Reed-Solomon 纠错；CRC 失败的页需重新采集。
2. 色板采样目前采用 RGB 最近距离，面对严重色偏、屏幕摩尔纹或强反光仍可能误判。
3. 当前 LZSS 采用纯 JavaScript 轻量实现，适合文本、JSON、CSV、代码和重复结构数据；对 JPEG、PNG、MP4、ZIP 等通常不会启用压缩。
4. 自动还原是前端内存内处理，不适合非常大的文件或数千页传输。
5. 历史协议与当前协议不可混用；历史多页样本必须做实际闭环验收。
6. 后续优先级：补齐 RS 纠错、完善历史多页兼容回归、增加真实摄像头实拍测试集、增加会话 ID 防止多批次页面混合。
